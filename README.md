# AI DataFlow

AI DataFlow is the production foundation for an AI data agency operating system: client management, AI-powered process analysis, and recommendation tracking.

## Production Architecture

- **Vercel** hosts the frontend and `/api/...` serverless functions.
- **Supabase** stores users, clients, and recommendation history.
- **Anthropic (Claude Sonnet 5.5)** generates live AI recommendations through `ANTHROPIC_API_KEY`. If that key is not set, the API falls back to OpenAI (`OPENAI_API_KEY`).
- The frontend never receives Supabase service keys or AI provider keys.

The older `server.js` remains as a local development fallback, but the recommended production path is Vercel + Supabase.

## Required Accounts

- GitHub repo
- Supabase project
- Vercel project connected to GitHub
- Anthropic API key (console.anthropic.com, with credits added). An OpenAI key is optional and only used as a fallback.

## Supabase Setup

1. Create a new Supabase project.
2. Open the Supabase SQL editor.
3. Run:

```text
supabase/schema.sql
```

This creates:

- `app_users` (with `role` and `active`)
- `clients` (with pipeline `stage`, `assigned_to`, appointment date and notes)
- `recommendations`
- `client_notes` (notes and activity timeline per client)

**Upgrading an existing database** (one that already has data): run `supabase/migrations/2026-10-20-shared-workspace.sql` instead. It only adds things, can be run more than once, and works with the code that is already deployed. Run it **before** deploying the matching code. Afterwards check the roles with `select email, role, active from public.app_users order by created_at;` (the oldest account becomes the admin; fix it with `update public.app_users set role = 'admin' where email = '...';`).

Then run `supabase/migrations/2026-11-11-client-discovery.sql` (adds one column, `clients.discovery`). Export CSVs of `clients`, `recommendations` and `client_notes` first: the Free plan has no automatic backups. The code works before and after this migration; until it has run, discovery answers cannot be saved and the page says so.

## Vercel Environment Variables

Set these in Vercel Project Settings:

```bash
SESSION_SECRET=use-a-long-random-secret
AGENCY_INVITE_CODE=choose-a-long-random-phrase
ANTHROPIC_API_KEY=your-anthropic-api-key
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-supabase-service-role-key
```

Optional:

```bash
ANTHROPIC_MODEL=claude-sonnet-5-5   # defaults to claude-sonnet-5-5; set only to override
OPENAI_API_KEY=                     # fallback provider, used only when ANTHROPIC_API_KEY is unset
OPENAI_MODEL=gpt-4.1-mini
ANALYSIS_DAILY_LIMIT=25             # analyses per person in any rolling 24 hours; defaults to 25
```

`SESSION_SECRET` is required on Vercel: if it is missing the API answers every request with a configuration error rather than signing logins with a public default. (Running the code on your own machine without it uses a throwaway value.) When a person reaches the daily analysis limit they see "Daily analysis limit reached" and can try again later; the limit counts saved analyses, so a failed run does not use a slot.

Every analysis stores the model that produced it and shows it on the results page and in History ("Generated by Claude Sonnet 5.5 (claude-sonnet-5-5)"). Analyses created before the switch have no model label.

Important: `SUPABASE_SERVICE_ROLE_KEY` must only live in Vercel environment variables. Do not put it in frontend JavaScript.

### Who can sign up

AI DataFlow is for agency staff only. The Create Account page asks for an **agency invite code**, which must match `AGENCY_INVITE_CODE` in Vercel. If that variable is not set, registration is closed and nobody can create an account (existing accounts keep working). Share the code only with people who work at the agency, and change it in Vercel (then redeploy) if someone leaves or the code leaks. Clients do not get logins in this version.

Sign-up asks for first name, last name, email, password and the invite code. There is no company field (everyone is agency staff; the stored company is the agency name), and the request cannot choose a role: every new account is written as **Sales**. The invite code field is plain text with auto-capitalize and autocorrect off, so it is typed exactly as shared; the code is case-sensitive.

### Roles and the shared workspace

The agency has **one shared workspace**: every staff member sees the same clients, analyses, notes and appointments. Each account has a role, enforced by the API (the screens only hide what a role cannot use):

| | Sales | Consultant | Admin |
|---|---|---|---|
| See every client, stage, appointment, note, analysis, price and ROI | yes | yes | yes |
| Create clients, edit customer info (phone, email, ...) | yes | yes | yes |
| Set stage, appointment and assign a consultant | yes | yes | yes |
| Add notes | yes | yes | yes |
| Download the client PDF | yes | yes | yes |
| Run, edit or delete analyses and their pricing | no | yes | yes |
| Record discovery answers (see below) | no | yes | yes |
| Delete a client | no | yes | yes |
| Clear all history, manage the team, reset a teammate's password | no | no | yes |
| Change your own password (Account page) | yes | yes | yes |

- New sign-ups start as **Sales**. An admin changes their role (or deactivates them) on the **Team** page. A deactivated person is locked out on their next click even if they are still logged in, and their history stays.
- Intended flow: Sales creates the client, books the appointment and assigns a consultant; the consultant meets the client, runs the analysis and moves the stage forward; everyone follows progress on the client page and the dashboard.
- Pipeline stages: Lead, Appointment set, Discovery, Analysis, Proposal sent, Won, Lost. Stage, assignment and appointment changes are written to the client's activity log automatically, with who did it.
- Appointments are stored as an exact moment and shown in each viewer's own time zone. There is no calendar sync yet.
- `clients.user_id` and `recommendations.user_id` mean "created by". Users who own records cannot be deleted (deactivate them instead).
- A user whose role is missing or unknown is treated as Sales (least privilege).

### Discovery questionnaire

SOP 001 (Stage 3) has the consultant ask the client a set of questions in the first meeting. They live in `lib/discovery.js`, which is the single source of truth: the API sends them to the client page, and answers for any other question id are refused. Eight sections apply to every client; an industry add-on appears only when the client's **Industry** matches a key in `INDUSTRY_ADDONS` (today only `real-estate`). Questions marked `star` are the ones to ask in the room (the SOP allows about 20 minutes); the rest are for a follow-up.

- Everyone can read the answers on the client page; only a consultant or admin records them (`GET`/`PUT /api/clients/:id/discovery`). Each save is written to the client's activity log.
- Answers are stored in `clients.discovery` as `{ answers, updated_at, updated_by }`. Answers for questions that no longer apply (for example after the industry changes) are kept but not shown or used.
- When an analysis is run for a client, the answers are added to the AI prompt, and a copy is saved on the analysis as `results.discovery`. The PDF prints the starred answers as "What we heard in discovery", except the budget, timeline and decision-maker section, which is sales information. Editing the answers later does not change an analysis that already exists.
- Figures (hours, people, hourly cost, volumes) are typed as free text for now; the ROI calculator planned for Phase 3 will read them.

### Passwords

- The app sends no email, so there is no emailed reset link. A teammate who forgot their password asks an admin, who clicks **Reset password** on the **Team** page. The admin sees a one-time temporary password (shown once, never stored in readable form) and passes it on privately. The person signs in with it and picks their own password on the **Account** page (click your name in the top bar).
- A login token is tied to the password it was issued under, so **changing or resetting a password signs that person out on every other device**. An admin cannot reset their own password; use Account > Change password.
- Deploying this change signs everyone out once (older tokens carry no password stamp). They just sign in again.
- There is no email change: the email is the login. Resets and changes need no database migration.

## Deploy

1. Push this project to GitHub.
2. Import the repo into Vercel.
3. Add the environment variables above.
4. Deploy.

Vercel will serve the HTML/CSS/JS files and run `api/index.js` for backend routes (`/api/*` is rewritten to it in `vercel.json`).

The Vercel build runs `npm run build`, which copies static assets into `public/`.

## Local Development

Quick local fallback:

```bash
npm start
```

For Vercel-style local API testing, use Vercel CLI:

```bash
vercel dev
```

## Production Notes

This is now a real app foundation, not a static demo. Before selling it to many customers, add:

- emailed password reset / email verification (today: admin-issued temporary passwords, no email at all)
- login rate limiting (nothing slows repeated wrong-password attempts except the hashing cost)
- custom domain
- database backups
- a client-facing portal (analysis, project progress, payment balance)
- file upload storage using Supabase Storage

## Operations Notes

- **Supabase free tier pauses** the database after ~7 days without traffic. The first request after a pause fails until the project is restored from the Supabase dashboard. Unpause before any client demo.
- **No automatic backups** on the free tier. Export data (Table Editor > Export CSV) before any schema change.
- All `/api/*` traffic is served by `api/index.js` via the rewrite in `vercel.json` (120s max duration; the AI call itself times out at 100s).

## Working With Analyses

- **Link to a client:** pick a client before generating, or add one inline (it is saved automatically when you generate). Afterwards, change the link from the Client dropdown on the results page or inside History > View Full Analysis. Choose "No client" to unlink.
- **PDF report:** use "PDF Report" on the results page or in the History detail popup. The PDF is generated in the browser and does not show the AI model name. Page 1 has the logo letterhead, an executive summary (written by the AI for new analyses, computed for older ones), the client profile, the scope of the analysis, the challenge as described, and a recommendations-at-a-glance table; the detail pages follow. Client **notes are internal and are never printed** in the PDF.
